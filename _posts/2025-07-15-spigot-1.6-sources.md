You may have read my article from a year ago, specifically the [section on
Wolvereness' DMCA of the CraftBukkit and Spigot
codebases](/blog/2024/01-01_spigot-dating-sucks#post-script) (or you'd know this
from wherever else—it's not a niche bit of old Minecraft sysadmin knowledge by a
long shot). The end result of this is that early 1.7 and prior Spigot releases
are effectively all lost media. If you'd like to run a server with an old Spigot
server JAR from that time, let alone develop using the Spigot API JAR[^apijar],
you'll need to rely solely on now-11-year-old links and the popularity of your
specific Minecraft version to get by.

[^apijar]:
	Technically, you _can_ use the standard server JAR as the API JAR. This is
	what I did for Thisway; it's quite useful when these binaries are
	effectively lost to time otherwise.

For me, that wasn't a problem. I ran a Spigot 1.6.4 server and wrote [a plugin
for it](https://www.spigotmc.org/resources/thisway.87115/) too, so I was able to
find a server _and_ API JAR despite the DMCA. This is called pure luck because
of 1.6.4's immense popularity (at least until 1.7.10, 1.8.9, and 1.12.2
shattered that).

<aside markdown="1">
### The legality of this&#x200B;/DMCA TL;DR
<small>#Not&#x200B;Legal&#x200B;Advice&#x200B;Im&#x200B;Just&#x200B;Some&#x200B;Loser&#x200B;Who&#x200B;Plays&#x200B;Minecraft</small>

I believe the DMCA (which is what I will henceforth refer to it as) boiled down
to this:
* Spigot is patch-based, and as such includes a few lines of Mojang's Mineacraft
  server code as an indicator to the patch applicator where the patch should be
  applied
* The Spigot additions are property of the Spigot contributors, licensed as LGPL
* The Minecraft server code is property of Mojang, licensed under the Minecraft
  EULA/proprietary license
* Given the Bukkit and Spigot repositories therefore contains bits of
  Mojang-licensed proprietary code, this means Bukkit and Spigot are
  distributing Mojang's code. This also means their own additions (licensed and
  copyright-owned under the LGPL by contributors) is being unlawfully included
  in the Mojang-copyrighted code

This means that this code, including Wolvereness' own contributions (LGPL
licensed and owned by him) had their copyright violated under these
distributions.

THIS MEANS THAT SpigotMC _cannot_ distribute the compiled binaries, as it
breaches Wolvereness' copyrights, given he wrote and released his code under the
LGPL license, yet it's being distributed under Mojang's EULA and copyright.
</aside>

This lack of available binaries makes stuff hard. Additionally, the Spigot
project used GitHub at this time, AFAIK. GitHub is a problem due to the fact
that [the original DMCA
request](https://github.com/github/dmca/blob/master/2014/2014-09-05-CraftBukkit.md)
was placed on that platform and nuked the original repositories of Spigot code.

As a result of this, SpigotMC does not support nor have facilities in place to
distribute these DMCA'd server versions—making them _really, really_ damn hard
to find.

> **Please do not dist&shy;ribute the binaries you create as a result of
> follow&shy;ing the instruct&shy;ions you find below**
> {:style="font-variant:small-caps"}
>
> **Doing so is a direct violation of the DMCA.** These binaries include code
> built on and including patched Minecraft classes. From the moment you run
> `./applyPatches.sh`{:.highlight.language-shell}, you will have a working
> directory that is <u>not</u> fit for distribution thenceforth!
{:.callout-error.fleft style="width:50%}

### Copyright notice regarding where we're getting this from
We will download code from the following locations:
* **SpigotMC Stash:**[^1][^2][^9][^10] This holds the current Spigot code. It
  does **not** contain any Mojang code that would trigger the DMCA
* **GitHub:**[^3]<sup>[\[Bukkit GitHub
  repo\]](https://github.com/Bukkit/Bukkit.git)</sup> These sources are for a
  standalone library Wolvereness made (a dependency of Spigot's API, IIRC), and
  the Bukkit API (which contains no Minecraft code)
* **`repo.md-5.net`:**[^4] This contains only Minecraft code, and no Bukkit
  contributor code, despite being labeled as an `org.bukkit` package. No Bukkit
  API exists in it, and so I can only assume it is devoid of LGPL and
  community-owned code. Therefore, it does not violate the DMCA
</aside>

Now lets get us some 1.6 stuff! We're gonna be fighting lots of ancient code and
workflows, so be prepared. You will require:
* Go ≥ 1.23
* Maven ≥ 3 <small>I'm assuming. Just stick to latest and you'll be fine</small>
* JDK 8 <small>Maybe ≥ 6 will work, given Minecraft at the time targets that,
  but I used OpenJDK 8 and was fine</small>
* POSIX shell (e.g. Bash, Zsh, Fish, the macOS terminal) <small>You _can_ use
  Windows with Git BASH or WSL or whatever, but **not** Command Prompt or
  PowerShell</small>

## Tutorial
### Part 1: Getting stuff
1. First, clone Spigot from where it lives nowadays:
   ```sh
   git clone https://hub.spigotmc.org/stash/scm/spigot/spigot.git && cd spigot/
   ```
   Wherever you cloned and have this `spigot/` directory, I will henceforth just
   call it `spigot/`.
2. Then, we need to checkout the last 1.6 version:[^1]
   ```sh
   git checkout 71d3b3b5ad6ffe5d74a98f563d9a36ee073ed7ed
   ```
3. This repository uses [Git
   submodules](https://git-scm.com/book/en/v2/Git-Tools-Submodules). However, it
   depends on Bukkit and CraftBukkit. Bukkit lives/lived on GitHub, and is still
   there (because it's not DMCA-infringing, see above); however, CraftBukkit
   _was_ zapped. Therefore, we need to use the modern CraftBukkit repository
   instead of the old, DMCA-infringing one.<br>
   Modify `.gitmodules` in the root of your `spigot/` repository directory and
   replace the following line:
   ```diff
   [submodule "CraftBukkit"]
   path = CraftBukkit
   -	url = https://github.com/Bukkit/CraftBukkit.git
   +	url = https://hub.spigotmc.org/stash/scm/spigot/craftbukkit.git
   ```
4. Let Git fetch our desired versions of the now-configured submodules. It'll
   figure it all out.
   ```sh
   git submodule update --init
   ```
   Git will get bingled on fetching the CraftBukkit repo, because the GitHub
   CraftBukkit and SpigotMC stash repos are not the same thing entirely (_so and
   so not DMCA'd code, as above…_). Therefore, we need to manually check out the
   last 1.6.4 commit:[^2]
   ```
   cd CraftBukkit/
   
   git checkout ff8b70fbb7a96b9d2ff078afcf3b3ff90f200981 && cd ../
   ```
5. Apply your patches![^5] <span style="color:#f00">Henceforth, your `spigot/`
   directory will be a violation of the DMCA _if_ you publish it online.</span>
   ```sh
   ./applyPatches.sh
   ```

### Part 2: Bodging it to work 11 years later
1. If you're using a relatively modern (not 2013-era) version of Maven, HTTP
   repository requests are blocked by default for security purposes. You must
   use HTTPS in your POMs. For this tutorial, we'll instead be bodging Maven to
   _not_ block HTTP. <u>This is insecure, and you should **not** do this in any
   other case!</u><br>
   Add the following to `~/.m2/settings.xml`:[^6]<br>
   <small>If you already have a Maven settings file, just add the `<mirror>`
   entry to your existing config</small>
   ```xml
   <settings xmlns="http://maven.apache.org/SETTINGS/1.2.0"
   	xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
   	xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.2.0 http://maven.apache.org/xsd/settings-1.2.0.xsd">
   	<mirrors>
   		<mirror>
   			<id>maven-default-http-blocker</id>
   			<mirrorOf>external:dont-match-anything-mate:*</mirrorOf>
   			<name>Pseudo repository to mirror external repositories initially using HTTP.</name>
   			<url>http://0.0.0.0/</url>
   			<blocked>false</blocked>
   		</mirror>
   	</mirrors>
   </settings>
   ```
2. #### OverMapped
   Now we need to set up a local copy of Wolvereness' library called
   _OverMapped_. It's independent of the Bukkit or Spigot projects, but was used
   in them for building certain stuff. It used to be on Maven Central, but today
   it isn't. Spigot-API requires version 0.0.2, so we will check out that from
   Wolfe's GitHub:
   ```sh
   mkdir -p ~/.m2/repository/com/wolvereness/overmapped/0.0.2/ \
   && cd ~/.m2/repository/com/wolvereness/overmapped/0.0.2/
   
   git clone https://github.com/Wolvereness/OverMapped.git tmp/ && cd tmp/
   
   git checkout da90bdcd8dec91e4994f462f21a65c8f1b3f2735
   
   mvn install
   ```
   Optionally, you can now remove the source code from your computer. You no
   longer need it, but you can keep it if so desired (for data hoarding :3); if
   you'd indeed like to remove it:
   ```sh
   cd ../; rm -rf tmp/
   ```
3. #### Minecraft server
   Go back to your `spigot/` directory, or some temporary directory. It doesn't
   really matter where we do this because we can just
   `rm`{:.highlight.language-shell} the two files we make at the end. I'll
   define `$TEMP_LOCATION`{:.highlight.language-shell} as the URL of the package
   we're working with for brevity:
   ```sh
   export TEMP_LOCATION="https://repo.md-5.net/repository/public/org/bukkit/minecraft-server/1.6.4/minecraft-server-1.6.4"
   
   curl -O "${TEMP_LOCATION}.jar" && curl -O "${TEMP_LOCATION}.pom"
   
   mvn install:install-file \
   -Dfile="minecraft-server-1.6.4.jar" \
   -DpomFile="minecraft-server-1.6.4.pom"
   
   rm -f "minecraft-server-1.6.4.jar" "minecraft-server-1.6.4.pom"
   ```
4. #### `AetherClassNotFound`{:.highlight.language-java} errors
   Another thing since the Maven setup in 2013 Spigot is so out-of-date is that
   Maven 3.1 and above use Eclipse Aether instead of Sonatype Aether. This means
   you'll probably get/have got
   `ClassNotFoundException`{:.highlight.language-java}s for
   `org.sonatype.aether`{:.highlight.language-java}
   classes/sub-packages.[^7]<br>
   As per the wiki article for [source 7](#fn:7), we can just do a dumb
   downgrade of the affected packages in `spigot/`. (First,
   `cd`{:.highlight.language-shell} back to your `spigot/` directory)<br>
   <u>For both of these, you'll get failures to refactor/build the Spigot
   server/API.</u> That's okay, because we haven't run a clean build yet, and
   so don't have all the libraries. (TL;DR we don't need to worry about it!!!)
	1. ##### maven-dependency-plugin
	   Revert to version 2.8, goal `tree`:
	   ```sh
	   mvn org.apache.maven.plugins:maven-dependency-plugin:2.8:tree
	   ```
	2. <aside class="fright" style="width:50%" markdown="1">
	   You could also just run the `mvn`{:.highlight.language-shell} command for
	   `2.0:shade`, and _not_ bodge the POM—but I haven't tested it.
	   </aside>
	   ##### maven-shade-plugin
	   {:style="clear:none"}
		1. First, bodge the POM for Spigot-Server. Change the following line in
		   <code>Spigot-Server/&#x200B;pom.xml</code>:

		   ```diff
		   <artifactId>maven-shade-plugin</artifactId>
		   -	<version>2.0</version>
		   +	<version>2.1</version>
		   ```
		2. Then, revert to version 2.1, goal `shade`:
		   ```sh
		   mvn org.apache.maven.plugins:maven-shade-plugin:2.1:shade
		   ```

### Part 3: Building! {#part3}
1. You can do any of the below for whichever combination of end JARs you want!:
	* #### Server and API JARs:
	  ```sh
	  mvn clean install
	  ```
	* #### Sources:
	  ```sh
	  mvn source:jar
	  ```
	* #### Javadocs:[^8]
	  We gotta add a flag for `maven-javadoc-plugin` to still build the JAR even
	  if we reach an error (which we get a lot of since the Spigot codebase has
	  tons of Javadoc syntax errors!):
	  ```sh
	  mvn javadoc:jar -Dmaven.javadoc.failOnError=false
	  ```

**Please** remember to undo the Maven HTTP bodge (`~/.m2/settings.xml`) from
earlier if you're ever going to work with Maven again!

## Post-script
If you've read [my Spigot ArrayIndexOutOfBoundsException blog
article](/blog/2024/01-01_spigot-dating-sucks.html) or [the Spigot Forums post
my article is based
on](https://hub.spigotmc.org/stash/projects/SPIGOT/repos/spigot/commits/6bba77bba39e616a8f2fc35ca48c482c77eba72e#CraftBukkit-Patches%2F0124-Enable-Improved-Ping-Sending.patch),
you may know of this bug and its patches. The patches for 1.6.4 for this bug as
built binaries are lost to time, but here's their code so you can perhaps revive
them (for personal use!!!):

There are multiple patch files named `Enable-Improved-Ping-Sending` in the
`spigot/CraftBukkit-Patches/` directory. They were released <u>in this exact
order</u>:
1. `0030`, signed off by Aikar, made some time before 1.6.4 Spigot entirely.
   This code persisted until March 26<sup>th</sup>, 2014, when the original
   strike of this bug occurred. **This is the version available in your local
   copy of `spigot/`.**
   
   This version iterates through the player list using `currentTick %
   numberOfPlayersOnline`{:.highlight.language-java}.
   `currentTick`{:.highlight.language-java} is determined by type-casting from
   system time (`long`{:.highlight.language-java}) down to an
   `int`{:.highlight.language-java}, thus enabling an overflow error where
   `currentTick`{:.highlight.language-java} can become negative
2. `0024`[^9], written by Thinkofdeath, was the first patch for this bug. All it
   does is replace the call of `currentTick`{:.highlight.language-java} with
   `abs(currentTick)`{:.highlight.language-java}, meaning negative values get
   forced positive. Nothing else is changed.
   
   Thinkofdeath pings Aikar (the original patch author) for a better solution to
   replace this temporary one
3. `0124`[^10], committed by Thinkofdeath—but probably written either directly
   by or in association with Aikar—was written a couple days later. Aikar came
   up with this algorithm: <small>Also, this explanation of the algorithm is
   more a guess because these are non-static methods and I don't really
   understand their implementation.</small>
	1. Instead of `index =
	   abs(currentTick)%numberOfPlayersOnline`{:.highlight.language-java}, we
	   rename `index`{:.highlight.language-java} to
	   `currentPing`{:.highlight.language-java}.
	   `currentPing`{:.highlight.language-java} is initalised to
	   `0`{:.highlight.language-java}
	2. For each player, when getting their ping,
	   `currentPing`{:.highlight.language-java} is set to
	   `(currentPing+1)%numberOfPlayersOnline`{:.highlight.language-java}.
	   Mathematically, $x+1 \bmod y$ yields a value that will
	   $\in [0,\mathrm{numberOfPlayersOnline}-1]$—which, conveniently, if you
	   have a list or array that is
	   `numberOfPlayersOnline`{:.highlight.language-java} long, means that
	   `currentPing`{:.highlight.language-java} will _always_ be a valid index
	   in that list or array.
	   
	   Conveniently again, I've abstracted the names of these variables.
	   `numberOfPlayersOnline`{:.highlight.language-java} is actually the
	   `#size()`{:.highlight.language-java} value of the player
	   `List`{:.highlight.language-java}, and in fact this ping function only
	   uses `currentPing`{:.highlight.language-java} as an array index! Meaning
	   it is **mathematically impossible** for an
	   `ArrayIndexOutOfBoundsException`{:.highlight.language-java} to occur!
	   <small>That is, assuming no race conditions or non-Thread-safe code, but
	   Minecraft is single-threaded and also shut up ♥</small>
   So Aikar has removed all calls to `currentTick`{:.highlight.language-java},
   and additionally has wrapped the entire function in a (redundant)
   `try`{:.highlight.language-java}-`catch()`{:.highlight.language-java} for
   sillies/safety/just in case™. Awesome!
   
   **If you're going to include a patch for this bug, I highly recommend this
   patch file!**
</aside>

That's it! Thanks for reading!
